# 0001 — No `.env` files anywhere on this machine; only `.env.template` with `op://` references

**Scope.** Every project on this machine — regardless of language, harness, or how it ships — gitignores real `.env` variants (`.env`, `.env.local`, `.env.*.local`, anything matching `.env*` except the template) at the user level, and commits at most one `.env.template` whose values are `op://` references rather than literal secrets; the canonical runtime is `op run --env-file=.env.template -- <command>`, which resolves the references in-process and never writes them to disk; the single, explicit exception to the `.env*` gitignore is `.env.template` itself, which is the only `.env*` file ever committed in any repo. **Why.** 1Password is the single source of truth for long-lived secrets, and `.env` files are forbidden in repos, `~/.config`, CI runners, and containers; an accidentally committed real `.env` is the most common credential-leak vector in personal projects, and banning the file shape entirely — rather than relying on careful per-repo `.gitignore` hygiene — turns the rule into a single mechanically-enforceable pattern (`.env*` minus the template) that catches the failure case at machine scope; the `op://` reference in `.env.template` is non-secret and useful documentation, naming exactly which 1P item powers the project.
